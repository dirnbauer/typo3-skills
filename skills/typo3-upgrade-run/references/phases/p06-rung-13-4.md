# P06 — Intermediate rung 13.4 (stateful iteration in loop 100)

Track `invariance`. **Conditional**: only for a v12 source with a real database.

TYPO3 documents major upgrades from the previous LTS, and core upgrade wizards ship per version. A
v12 database that jumps straight to 14.3 skips every 13.4 wizard, and those wizards are how persisted
data gets migrated.

## Preconditions
Loop 100 open. Source is v12. Take a fresh snapshot immediately before `extension:setup` or the
first wizard; do not create another parent loop.

## Steps
1. Require `^13.4`; make the installation boot.
2. `ddev typo3 extension:setup`.
3. List and review the applicable 13.4 Core/extension wizards and prerequisites, then execute them
   through Core `upgrade:run <identifier>` after the required snapshot/approvals. Do not substitute
   a custom migration script or run optional destructive wizards indiscriminately.
4. Verify `ddev typo3 upgrade:list` reports no necessary wizards. Its exit code alone is not proof.
5. Visual spot-check of the sample against A — **informational only**. The 13.4 rung is not the
   invariance claim, but a large difference here is an early warning worth acting on now rather than
   discovering at loop 300.

## Exit
`upgrade:list` empty on the 13.4 rung; schema comparison clean. This is the stateful fixed-point
evidence for the parent iteration.

## Blocking
A failed wizard. Restore the operation snapshot, fix the cause, record the next parent iteration. Never continue on a half-migrated
database.

## Note
Save the code modernisation for the v14 rung. Modernising at 13.4 means doing it twice.

## When something breaks on this rung

Check [`references/known-problems.md`](../known-problems.md) before diagnosing from scratch. The
faults this rung produces are repetitive across projects: an SQL syntax error from a database engine
below the DBAL floor, a `NOT NULL` violation from a column a removed feature left behind, and pages
that return 200 while logging a warning for a property v13 dropped and v14 deletes.
