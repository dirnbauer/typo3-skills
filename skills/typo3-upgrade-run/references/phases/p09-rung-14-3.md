# P09 — Rung 14.3 execution (stateful iterations in loop 100)

Track `invariance`. The upgrade itself.

## Preconditions
P08 migration findings closed. Take a fresh snapshot immediately before each stateful command group.

## The fix pack first
Fleet sites met the same TYPO3 14 problems on this rung, one diagnosis round each. Apply the
[TYPO3 14 fix pack](../typo3-14-fix-pack.md) instead of waiting for the symptoms:

1. Run its read-only probe before the Composer step; the output is one artifact.
2. Composer to 14.3; when the first update aborts on class-alias-loader, `composer install`
   ([item 11](../typo3-14-fix-pack.md#11-composer-aborts-at-the-14-rung)).
3. After the wizards (step 3 below), check the module grants
   ([item 8](../typo3-14-fix-pack.md#8-renamed-modules-and-editor-rights)); restore only with the
   intake approval.
4. Apply every remaining hit, one commit per item, then rerun the probe and the readiness checks.
5. The first 14.3 smoke run includes a module sweep as admin and as a non-admin editor
   ([item 7](../typo3-14-fix-pack.md#7-backend-modules-refused-to-admins)).

The evidence carries the pack table: per item detected, applied, proof and approval.

## Steps
Apply [native-tool selection and side-effect guards](../native-tools-first.md). Reuse registered
Core commands instead of writing bootstrap/schema/cache helpers; review exact installed behavior.

1. `ddev typo3 extension:setup` — the Core command that creates tables/fields and applies add/change
   schema operations. A stale obsolete `NOT NULL` column can block this command or the first runtime
   write; resolve that exact, evidenced blocker from the fresh snapshot instead of repeatedly retrying
   a half-migrated database.
   `--extension=key` does not restrict schema comparison to that package in inspected Core 14.3.7;
   it restricts package setup hooks. Review the whole schema delta and static-data/config effects.
2. Immediately review the **remaining** schema comparison in the backend database analyzer in Admin
   Tools. `database:updateschema "*.add,*.change" --dry-run` is an additional preview **only** where
   the project already ships `helhum/typo3-console`; that command is not Core. Review all eight
   operation classes and prove data/workspace safety before prefix/drop cleanup per
   `references/database-integrity.md`. Do not describe this as pre-approval for step 1: Core has
   already applied its add/change setup operations, whose data impact also needs review.
3. `ddev typo3 upgrade:list`, then the reviewed `upgrade:run` steps. Read the remaining-wizard list;
   exit 0 from the listing does not mean every migration has completed. Never skip
   `setup_userSettingsScrubbingMigration` (#109585), also not on a direct 13.4 → 14.3 run: keep the
   user-settings wizards in registry order and confirm no non-empty `password`/`password2` value
   remains ([typo3-security v14 notes](../../../typo3-security/references/v14-notes.md)).
4. Re-run `site:list`, `site:show <site-identifier>`, `site:sets:list` and `ddev exec locale -a`;
   block on an unavailable locale, selected set or set dependency. Then run `referenceindex:update`,
   `language:update`, `cache:flush` and `cache:warmup`.
5. Log in to the backend at the DDEV URL. Inspect Admin Tools environment and upgrade status,
   the database analyzer state, and the remaining wizard list once after the command group.
   Return remaining root causes to the parent graph for a bounded recovery; do not start a nested
   cleanup programme. The exit still requires clean evidence.

## The warm-up deprecation is not noise
Cache warm-up must not emit the #108345 package-metadata deprecation. When it does, fix the
extension's `composer.json` (`version` / `providesPackages`) rather than ignoring the message — v15
stops evaluating `ext_emconf.php` entirely, and this is the warning that the metadata is not where it
needs to be.

## When something breaks on this rung
Check [`references/known-problems.md`](../known-problems.md) first. On the fleet's 14.3 rungs: every
page 500 from `INCLUDE_TYPOSCRIPT` left in `.txt` files, RTE tags escaped after fluid_styled_content's
parseFunc removal, empty lists from site-package classes extending changed core classes, relative
asset URLs no longer prefixed, re-rendered processed images and the new sitemap parameter. A symptom
the fix pack names but its detection missed is a finding for `rung14-recovery`, not a blind patch.

## Exit
Schema comparison clean. Every wizard run, or consciously skipped with a recorded reason — except
`setup_userSettingsScrubbingMigration`, which always runs. Reference
index and relation checks recorded. Warm-up emits no #108345 deprecation.

## Blocking
Any failure — restore the operation's snapshot, fix the cause, and record a new parent iteration.
Never continue on a half-migrated database and never hide retries inside a nested tool loop.
