# Backend previews that editors can read

Content Blocks renders `templates/backend-preview.fluid.html` (or `backend-preview.html`) in the page
module. Previews generated by a migration (the Mask importer, `make:content-block`) dump every field:
full-size images, debug values, a bare "Link". Replace them with one shared design. The pattern below
was built on a relaunch site and then applied to 24 migrated elements of a TYPO3 14.3 site.

## The card

Every preview is one card: an accent bar on the start edge, the element type as a small uppercase
label, the record's title, a cropped text, badges with the key facts, and a thumbnail when the element
has an image. A collection lists its items (see below). One stylesheet serves all blocks:

```html
<html xmlns:f="http://typo3.org/ns/TYPO3/CMS/Fluid/ViewHelpers"
      xmlns:cb="http://typo3.org/ns/TYPO3/CMS/ContentBlocks/ViewHelpers"
      xmlns:core="http://typo3.org/ns/TYPO3/CMS/Core/ViewHelpers"
      data-namespace-typo3-fluid="true">
<f:layout name="Preview"/>

<f:section name="Header">
    <f:if condition="{data.title_field}"><cb:link.editRecord uid="{data.uid}" table="{data.mainType}">{data.title_field}</cb:link.editRecord></f:if>
</f:section>

<f:section name="Content">
    <f:asset.css identifier="site-package-backend-content-blocks"
                 href="EXT:site_package/Resources/Public/Css/backend-content-blocks.css"/>
    <div class="content-block-preview content-block-preview--with-media">
        <f:if condition="{data.image.0}"><f:image image="{data.image.0}" width="320" height="220c" class="content-block-preview__image"/></f:if>
        <div class="content-block-preview__body">
            <div class="content-block-preview__eyebrow"><f:translate key="{cb:languagePath()}:title"/></div>
            <div class="content-block-preview__title">{data.title_field}</div>
            <p class="content-block-preview__text">{data.bodytext -> f:format.stripTags() -> f:format.crop(maxCharacters: 180)}</p>
        </div>
    </div>
</f:section>
</html>
```

- **The `Preview` layout has three sections.** `Header` fills the element's header line, `Content` its
  body, `Footer` its footer. A section that exists but renders empty leaves its slot empty; a section
  that is missing falls back to the standard preview of that slot. Put the record's own title in
  `Header` only when there is one: falling back to the type name repeats it a third time beside the core
  header and the eyebrow.
- **Labels come from the block itself.** `{cb:languagePath()}` returns the block's `labels.xlf` path:
  `<f:translate key="{cb:languagePath()}:title"/>` for the type name, `…:<field>.label` for a field and
  `…:<collection>.<field>.items.<value>.label` for a select item. Generic words (no title, entries,
  more) go into one site-package `locallang_be.xlf` with ICU plurals:
  `{count, plural, one {# entry} other {# entries}}`.
- **Light and dark mode.** TYPO3 14 switches the backend scheme through `color-scheme` and CSS
  `light-dark()`. Take surfaces and text from the backend tokens (`--typo3-surface-container-low`,
  `--typo3-surface-bright`, `--typo3-text-color-variant`, `--typo3-component-border-color`) and write the
  accent as `light-dark(<dark brand colour>, <light brand colour>)`. Put icon thumbnails (often black line
  art) on a light tile in dark mode, or they disappear.

## Collections: list the items, not the core grid

The `PageLayout/Grid` partial that migrated previews use renders every child as a page-module card. For
a collection whose children are not `tt_content` records, the card header shows the content-type label,
which these records do not have, and the body stays empty: editors see a column of empty cards with
edit buttons. List the items yourself:

```html
<f:variable name="itemCount" value="{data.items -> f:count()}"/>
<ul class="content-block-preview__items">
    <f:for each="{data.items}" as="item" iteration="iterator">
        <f:if condition="{iterator.index} < 6">
            <li class="content-block-preview__item">
                <f:if condition="{item.image.0}">
                    <f:then><f:image image="{item.image.0}" width="80c" height="80c" class="content-block-preview__item-thumb"/></f:then>
                    <f:else><span class="content-block-preview__item-thumb content-block-preview__item-thumb--empty">{iterator.cycle}</span></f:else>
                </f:if>
                <span class="content-block-preview__item-body">
                    <span class="content-block-preview__item-title">{item.title}</span>
                    <span class="content-block-preview__item-meta">{item.position}</span>
                </span>
                <be:link.editRecord uid="{item.uid}" table="{item.mainType}" contextual="1" class="content-block-preview__item-edit"
                                    title="{f:translate(key: 'LLL:EXT:site_package/Resources/Private/Language/locallang_be.xlf:backend.edit_item')}">
                    <core:icon identifier="actions-open" size="small"/>
                </be:link.editRecord>
            </li>
        </f:if>
    </f:for>
</ul>
<f:if condition="{itemCount} > 6">
    <f:variable name="moreCount" value="{itemCount - 6}"/>
    <div class="content-block-preview__more"><f:translate key="…:backend.more" arguments="{count: moreCount}"/></div>
</f:if>
```

- `be:link.editRecord uid table contextual="1"` (namespace `xmlns:be="http://typo3.org/ns/TYPO3/CMS/Backend/ViewHelpers"`)
  opens the item in TYPO3 14's side panel, so the editor changes one item without leaving the page.
  `cb:link.editRecord` takes `record`, `uid`, `table`, `fields` and `returnUrl` but has no `contextual`
  argument (Content Blocks 2.4.9 source, verified 2026-10-31).
- Counts per status work with Fluid arithmetic inside the loop: initialise `<f:variable name="sold"
  value="0"/>`, then `<f:variable name="sold" value="{sold + 1}"/>` in a `f:switch` case.
- Show six to eight items and a "+ N more" line; a lot plan with 30 rows is still one glance.

## Field values that are not strings

- A `Link` field arrives as a `TypolinkParameter` object without `__toString()`: printing `{data.link}`
  fails. Use `{data.link.url}` and make page links readable with
  `{data.link.url -> f:replace(search: 't3://page?uid=', replace: 'Page ')}`.
- Plain-text fields that hold link targets (`122`, `133#924`, `file:501`) are strings; crop them.
- Rich text: `{data.bodytext -> f:format.stripTags() -> f:format.crop(maxCharacters: 180)}`.

## Child rows rendered through the parent's preview

On TYPO3 14.3 a migrated preview can take the page module down with `#1775553111 Record property
"X" is not available` (`Render/TextViewHelper`). The Mask importer's previews render every
collection with `PageLayout/Grid`, which is meant for blocks with their own record table. For a child
table defined inside a block, Content Blocks picks the **parent** block's `backend-preview.html` for
the child row, so `{data -> f:render.text(field: 'header')}` runs against a row that has no `header`.
Child rows whose fields happen to exist render silently with wrong output. `ctrl.hideTable` is not
the cause.

- Where the source had its own backend template, use it as the `Content` section and list the
  children in a plain `f:for` loop ([collections](#collections-list-the-items-not-the-core-grid)),
  never through `PageLayout/Grid`.
- Where the source had none, delete the generated `backend-preview.html`; the TYPO3 standard
  preview is what editors saw before.
- Use `f:sanitize.html`, not `f:format.html`, in backend templates on TYPO3 14 (`#1686813703`).

Detection and the upgrade context: [Mask → Content Blocks](../../typo3-upgrade-run/references/mask-to-content-blocks.md#backend-previews-that-crash-on-143).

## Inline records in the edit form

The inline (IRRE) header of each child shows the child table's label. Content Blocks picks the first
suitable field when `labelField` is missing; for migrated collections that is often a link, an address or
an e-mail. Set it on the Collection:

```yaml
- type: Collection
  identifier: tx_team_member
  labelField:
    - name
    - position          # shown as "Name, Position" (label_alt with label_alt_force)
```

A single `labelField` can carry `fallbackLabelFields` (used when the label is empty). Do not combine a
list `labelField` with `fallbackLabelFields`: Content Blocks 2.4 writes the fallbacks into `label_alt` and
keeps `label_alt_force`, so the fallbacks replace the second label field in every title.
TYPO3 14 renders no thumbnail in inline headers; the page-module preview carries the pictures.

## Verify

Lint (`content-blocks:lint`), confirm no schema change (`extension:setup` reports nothing to do;
`database:updateschema '*.add,*.change' --dry-run` exists only with helhum/typo3-console) and look at
the page module in both colour schemes. After a migration, probe every page
that carries Content Block elements, child rows included, and require 0 exceptions; a frontend
comparison never renders a preview. Probe on a clone: previews with `f:image` write image derivatives
(and sidecars of WebP extensions) into `fileadmin`. In a browser test the module content
lives in the backend's `list_frame` iframe: query that frame, not the top document. Frontend output does
not change: compare the frontend responses before and after.
